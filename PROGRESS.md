# Доработка в 3 этапа — ход работы

Файл ведётся по ходу работы: что сделано, что осталось, как проверить.
Если сессия оборвалась — продолжать с первого незакрытого пункта.

## Как запускать проверки

```
# бэкенд (временная база создаётся и удаляется сама, ИИ — заглушка)
cd backend
.venv\Scripts\python -m unittest discover -s tests -t .

# фронтенд
cd frontend
npm test          # формулы: команды сервера сверяются с KaTeX, вставки, предпросмотр
npx tsc -b
npx oxlint
```

## Этап 1. Формулы — ГОТОВО

Сделано:
- KaTeX из npm, шрифты локально (в `/assets`), отдельным куском: страницы без формул его не грузят.
- `$...$` и `$$...$$` рисуются на странице ученика (задание, варианты, экран результата),
  в таблице проверки (клетка и редактор), в разборе работы на странице результатов.
  Битая формула показывается исходным текстом с подчёркиванием. Текст без `$` — как раньше.
- CSP: KaTeX рисуется через DOM (`katex.render`), `'unsafe-inline'` не нужен; шрифты — файлами
  (`assetsInlineLimit: 0`). Проверено в headless-Chrome со строгой политикой
  `default-src 'self'; style-src 'self'; font-src 'self'`. Комментарий — в `deploy/Caddyfile-snippet`.
- Промт (серверный и для копирования): формулы только в `$...$`, школьная запись, ответ для
  «ввода» без разметки.
- Сервер: `app/formulas.py` — разбор школьного LaTeX. Незакрытый `$`, непарные скобки,
  неизвестная команда → needs_review «ошибка в формуле: …». `\frac` с одной чертой в JSON
  от ИИ чинится (`fix_latex_escapes`).
- Проверка ответов и самопроверка: `\frac{a}{b}` == `a/b`, `2{,}5` == `2,5`, «−» == «-»;
  смешанное число `2 1/3` больше не склеивается в `21/3`.
- Редактор задания: панель вставок (дробь, степень, индекс, корень, ·, :, ≤, ≥, ≠, π, °)
  в позицию курсора, живой предпросмотр, подсказка «формулы — между знаками $».
- Ученик: под полем ответа предпросмотр (3/5 → дробь, 2^3 → степень, 2 1/3, sqrt(2)).

Что знать:
- Серверная проверка формул — приближение KaTeX: редкую команду KaTeX нарисует, а сервер
  пометит задание «ошибка в формуле» (учитель посмотрит и снимет отметку).
- Содержимое `csp_default` лежит на сервере, в репозитории его нет — см. комментарий в сниппете.

## Этап 2. Роли и ссылки по классам — ГОТОВО (миграция 010 НЕ накачена на kr_tests)

ВАЖНО: код этапа 2 ждёт миграцию 010. Пока она не накачена на рабочую базу, сервер
на новом коде отвечает 503 «на сервере ещё не обновлена база данных».

```
cd backend
psql -U postgres -d kr_tests -f migrations/010_class_links_roles.sql
# откат (аннулированные попытки и журнал прав при откате удаляются):
psql -U postgres -d kr_tests -f migrations/010_class_links_roles.down.sql
```

Сделано:
- Миграция 010 + down: `test_classes` (ссылка, приём и очередь вариантов на класс),
  `tests.links_by_class`, `attempts.class_id / device_id / name_key / annulled_at`,
  `admin_log`. Старым работам тоже выдаются ссылки классов; их общая ссылка работает как раньше.
  Накат на старые данные, откат и повторный накат проверены тестом.
- Ученик: `/t/<код класса>` — класс задан ссылкой, вводится только ФИО. Одна попытка на
  ученика в классе (ФИО без учёта регистра и ё/е) и одна сданная работа с устройства в рамках
  одной ссылки класса; другой класс на тех же компьютерах проходит свободно.
  Варианты раздаются по очереди внутри класса.
- Страница работы: таблица классов (ссылка, «Скопировать», число сдавших, «Открыть/Закрыть
  приём»), «Добавить класс» → новая ссылка, «Разрешить пересдачу» (старая попытка —
  «аннулирована», в умения, итоги, статистику и Excel не идёт). Браузер ученика сам
  сбрасывает запомненный результат аннулированной попытки.
- «Статистика» в меню учителя (`/stats`): только его работы, по классам и умениям, фильтр по
  работе. Сервер добавляет условие «автор — я» ко всем выборкам; чужая работа по id → 403.
  Администратор видит всю школу и разрез по учителям.
- Админка «Учителя»: «Сделать админом» / «Снять права» с подтверждением; нельзя снять с себя
  и с последнего действующего администратора; журнал (`admin_log`) внизу страницы.
- Если база старее кода — ответ 503 с понятным текстом и одна строка в логе (а не трассировка).

Что знать:
- У НОВЫХ работ общей ссылки нет (иначе защита по устройству обходилась бы выбором класса).
- Метка устройства живёт в памяти браузера: режим инкогнито её обходит, тогда остаётся
  правило «один ученик — одна попытка».
- Если в кабинете компьютеров меньше, чем учеников в классе, второй ученик на том же
  компьютере по той же ссылке не начнёт — так задано в постановке.
